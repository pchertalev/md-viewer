# md-viewer

Десктопный просмотрщик Markdown для Windows: окно с вкладками, рендер через Chromium,
оглавление, темы, ассоциация файлов `.md` и один экземпляр приложения на все открытия.

Идея простая: markdown читается один раз, превращается в обычную HTML-страницу и показывается
в настоящем браузере внутри приложения. Никаких своих раскладчиков текста — вёрстку делает
Chromium, поэтому таблицы, код, списки задач и вложенные цитаты выглядят так же, как в браузере.

## Что умеет

- открывает файл двойным кликом в проводнике, из командной строки и по ссылке из другого markdown;
- вкладки: несколько документов в одном окне, переход по соседним файлам;
- оглавление слева, счётчики слов и времени чтения, путь к файлу в шапке;
- темы: светлая, тёмная, «как в системе»; масштаб текста (Ctrl +/−); ширина текста Ctrl+Shift+W — на всё окно (по умолчанию), узкая колонка, средняя;
- подсветка кода (highlight.js), таблицы, сноски, списки задач, `~~зачёркнутый~~`;
- картинки и вложения по относительным путям — от папки открытого файла, а не от папки процесса;
- внешние ссылки уходят в браузер, ссылки на `.md` открываются этим же приложением;
- один экземпляр: второй запуск не поднимает новое окно, а передаёт пути живому;
- регистрация в реестре Windows (`HKCU`, без прав администратора).

## Требования

Нужен **JetBrains Runtime с JCEF** — это JBR, в который встроен модуль `jcef` и бинарники
Chromium (`jcef.dll`, `jcef_helper.exe`). Обычная JDK-сборка не подойдёт: модуля `jcef` в ней нет.

Скачать: <https://github.com/JetBrains/JetBrainsRuntime/releases> — ищите сборку с суффиксом
`jbrsdk_jcef` (например `jbrsdk_jcef-17.0.14`). Распакуйте в удобную папку, например
`~/.jdks/jbrsdk_jcef-17.0.14`, и укажите её в `gradle.properties`:

```properties
org.gradle.java.home=C:/Users/pavel/.jdks/jbrsdk_jcef-17.0.14
```

Компилятор и запуск должны видеть один и тот же рантайм: `jcef` — модуль рантайма, а не библиотека
из Maven Central.

## Сборка и запуск

```bash
gradlew.bat test                 # тесты ядра: чтение файлов, постобработка HTML, настройки, IPC
gradlew.bat run --args="samples/demo.md"
gradlew.bat installDist          # готовый classpath в build/install/md-viewer
```

Запуск напрямую, без Gradle:

```bash
"%JAVA_HOME%\bin\java.exe" --add-modules jcef ^
  -cp "build\install\md-viewer\lib\*" ru.mdview.MainKt "D:\docs\README.md"
```

## Служебные команды

```
MdViewer.exe --register      прописать .md в HKCU\Software\Classes
MdViewer.exe --unregister    убрать за собой
MdViewer.exe --status        кто сейчас открывает .md
MdViewer.exe --exe <путь>    для --register указать реальный exe (в разработке подставляется обёртка)
```

Регистрация работает в `HKCU` — права администратора не нужны. Одно ограничение Windows обойти
нельзя: выбор приложения пользователем лежит в защищённом ключе `UserChoice`, и приложение не
может его перезаписать. Если `.md` уже отдан другому просмотрщику, `--register` это скажет,
а способ переключения будет в подсказке (`--status`).

## Как устроено

```
ru.mdview.core    файл на диске → markdown → HTML (flexmark, расширения GFM)
ru.mdview.html    постобработка HTML (Jsoup), сборка страницы из шаблона, складывание в кэш
ru.mdview.ui      окно на Swing + браузер JCEF, вкладки, мост JS ↔ Java
ru.mdview.ipc     один экземпляр: сокет на 127.0.0.1 и метка процесса в профиле
ru.mdview.platform реестр Windows и ассоциация файлов
ru.mdview.app     настройки, пути профиля, связка «файл → страница»
```

Путь один: `DocumentPipeline` читает файл, отдаёт markdown в flexmark, результат правит
`HtmlPostProcessor` (оглавление, относительные пути, пометка внешних ссылок), затем
`PageComposer` подставляет тело в шаблон `page.html`, а `PageWriter` кладёт страницу в кэш
профиля. Окно получает только файл страницы и загружает его по `file://`.

Страница — именно файл, а не `loadHTML`: иначе страница не сможет подтянуть картинки по
относительным путям и свои же css/js. Кэш лежит в `%LOCALAPPDATA%\md-viewer\cache`, держим
последние страницы, старые чистятся сами.

Мост JS ↔ Java — `CefMessageRouter` с функцией `mdviewQuery`: кнопки на странице (тема,
масштаб, содержание) уходят в приложение, а не живут в js.

## Статус

Проект в работе. Что уже есть и покрыто тестами: чтение файлов (UTF-8, BOM, внятные ошибки на
чужую кодировку), разбор markdown, постобработка HTML, оглавление, настройки, один экземпляр,
команды реестра.

Что сейчас чинится:

- **артефакты отрисовки в JCEF** — та же страница в обычном Chrome рисуется корректно, в окне
  приложения текст местами накладывается друг на друга; причина в связке JCEF + оконный режим,
  ищется;
- перетаскивание файла в окно: тяжёлый child-хэндл браузера перехватывает жесты;
- сборка единого образа через `jpackage` — ассоциация в собранном виде проверяется на нём.
